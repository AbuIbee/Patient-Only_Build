## Defects found only by real execution, not caught by Codex's static review 004

1. **PL/pgSQL variable/alias collision (crash on every run).** The draft's identity and drift-check subqueries used `pg_policies p` as a SQL alias while the surrounding DO block's own loop variable was also named `p` (declared `record`, unassigned until the FOR loop runs). PL/pgSQL resolves `p.field` against its own unassigned variable first, raising `record "p" is not assigned yet (SQLSTATE 55000)` before a single policy could be validated. **The draft, as committed to PR #4, had never been run successfully against a real PostgreSQL instance.** Fixed by renaming the live-catalog alias to `lp` everywhere it is not the loop variable.

2. **Stale predicate assumption (would have broken every check-in submission).** The free-tier check-in guard correction assumed the pre-migration-152 predicate (`patient_has_paid_entitlement(patient_id)` + a `caregiver_patients` check) was still current. Migration `152_codex002_p1_08_local_entitlement_oracle_lockdown.sql` -- applied well after the stale baseline/fresh-catalog snapshot the draft was reasoned from -- replaced that predicate with a bare, self-scoped `my_patient_has_paid_entitlement()` call and **revoked `authenticated`'s EXECUTE on the raw function entirely** (service_role only now). Had the original draft been applied as written, every check-in INSERT -- not merely unauthorized ones -- would have failed with `permission denied for function patient_has_paid_entitlement`. Fixed to OR the existing self-scoped call with the new staff branch, preserving migration 152's own self-scoping decision.

3. **Anonymous-access regression (401 instead of 200+[]).** Every one of the 29 upgraded policies, plus the two check-in guards, previously carried no `TO` clause (applied to every role, anon included) -- harmless while their content never called a privilege-gated function. The guarded form calls `hcn_current_staff_patient_access()`, correctly revoked from anon; applying it to a still-`{public}`-scoped policy turned "RLS returns an empty result for anon" into a hard `401 permission denied for function hcn_current_staff_patient_access`, confirmed live against a real anonymous REST read of `patients`. **Migration `106_r34_scope_rls_embedded_checks_to_authenticated.sql` already established and proved the fix for this exact class of defect for a disjoint set of 56 policies** (`ALTER POLICY ... TO authenticated`, retargeting role scope without touching USING/WITH CHECK logic). Applied here, in the same statement as each row's content upgrade.

## Honestly scoped limitation (owed to Codex at hand-off)

Exact-occurrence counting on named anchors (`patient_id = auth.uid()`, `caregiver_patients`, `caregiver_id = auth.uid()`, the helper call) proves the one historical-only check-in guard (`FQA-019/SEC-008`) has the correct disjuncts exactly once and a correctly-argued helper call -- it does **not** constitute a full canonical whole-expression equality proof against committed ground truth, because no committed baseline in this repository contains that specific policy's original full text (the fresh/reviewed baseline catalog predates it; it was observed only in a production catalog snapshot this repository does not hold). An adversarial OR-true-style branch appended entirely outside the anchored span would not be caught by this validator for that one specific policy. **Independent Codex review against the actual captured historical snapshot remains required before this is treated as a complete closure of S01-R1/S02-R3 for that one policy.** Every other policy in scope (including the other, fully-ground-truthed check-in guard and all 29 manifest rows) does not share this limitation, since their original and extended full text was verified directly, live, against the actual running catalog.
