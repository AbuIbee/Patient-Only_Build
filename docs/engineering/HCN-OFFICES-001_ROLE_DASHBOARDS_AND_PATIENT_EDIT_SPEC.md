## 1. Measurable dashboard contract (ALL offices)
- Every metric must be computed from an actually available authenticated tenant-scoped source, with explicit UTC snapshot age, loading state and unavailable/partial status. NEVER show 0 for query failure or pretend billing/AI predictions have data.
- Metric and alert cards are clickable buttons or links with an accessible name, keyboard focus, actual navigation to the *filtered underlying records*, and browser history/deep-link restoration. If a feature does not yet have a functioning destination, show \`Not available\` with an identified issue; no inert decorative controls.
- Implement one server authorization gate for each read/write and one per-office filtered data projection. Never use only sidebar visibility as security. Owner controls their organizations but does not become Platform Owner.
- Each alert contains record_id, org_id, patient_id if permitted, priority, age, reason and action. Aggregations must not leak patient identity between tenants.
- Desktop layouts 1280/1440px; mobile 320/375/390/430px; tablet 768/1024px. Caregiver touch target >=44x44 CSS pixels; real screen-reader labels, WCAG 2.2 AA color/keyboard behavior.
- 95th percentile targets measured on representative data: dashboard initial usable content <=2.5s on average 4G and action navigation <=0.5s after data is cached; if unproven label benchmark NOT MEASURED. No live PHI in telemetry.
- All data mutations require visible pending/success/error and idempotent retry. Use optimistic writes ONLY where offline queue is independently durable and authorization remains valid on sync.

## 2. OFFICE A: ORGANIZATION OWNER / BUSINESS CONTROL CENTER
Separate from Platform Owner and Director. Owner screens: license/plan, annual-first-year vs recurring monthly obligations, organization census, staff and credential requirements, Directors, capacity, contracted service status, invoice exceptions, unsigned agreements, organization-level incidents, cross-organization overview for a multi-org Owner. Owner may view legitimate organization scope but no global cross-customer analytics. Drill-down action \`Open Billing\` must show authenticated provider-confirmed state, not fictional revenue. Primary controls: Manage organizations, select Director, Staff, Patients, Agreements, Licensing, Billing, Incidents, Audit.
Proposed nice-to-have: grouped organization comparisons, weekly board export (authorized scope), predictive staffing needs only after historical data exists.

## 3. OFFICE B: DIRECTOR — STRATEGIC COMMAND CENTER
Hero: \`Today / This Week\`, red/amber/neutral priority queue, current census and scheduled-visit adherence. Metrics & contract:
- Scheduled visits today count, completed count, missed/late visits, fill rate \`filled required slots / required slots\` with explicit denominator and timezone. Click->Scheduling Oversight filtered by status/time.
- Patient census active; visits due per 15-minute interval; unassigned patient caseload; clients with no responsible contact or overdue intake acknowledgment; click->patients/assignments filtered.
- Staffing capacity by 1-hour buckets: active scheduled caregivers vs requested patient visits; include required skills and specialist entitlements, not just raw headcount; click->staffing conflict view with exact time windows and patient/visit IDs.
- Open incidents, missed EVV, expired/expiring professional credentials, unsigned clinical brief acknowledgments and pending representative reviews; click->specific incident/credential/review.
- Financial visibility: actual license and subscription status; billed/unbilled visits and payer claim risk ONLY if an integrated revenue/claims data source exists, else \`Not connected\` and no synthetic dollars or inferred reimbursement.
- Every KPI drills to patient, staff, visit, or invoice source; dashboard actions must work without sidebar.
- Optional forecasting: 30-day attendance/staffing prediction only after >=30 days sufficient history and validated holdout metrics; show interval and rationale, never a bare authoritative risk score. Patient-flow heatmaps only for actual clinic/location workflow (not home care if irrelevant).
- One-click PDF/Excel reports through authorized reporting backend with reproducible query snapshot and source dates; no client-made export of unauthorized PHI.
**First code increment on this branch:** current four Director cards become keyboard-accessible navigational buttons and six direct workflow quick actions are added. NOT YET a full metrics backend.

## 4. OFFICE C: ENTERPRISE CAREGIVER — MOBILE ACTION HUB
Show TODAY, not organization-wide financials. Sequence: critical safety alerts + unacknowledged patient assignment / changed care plan -> next scheduled visit with time, distance/directions (only when address is available/authorized) -> Clock In/Out -> patient-specific checklist -> observations and medication reminders -> handoff -> secure communication.
- Visit cards with patient initials, address disclosed only for assigned patient, visit window and status, tap directions opens maps using authorized destination, not automatic tracking. Schedule changes flagged by server history.
- EVV: record all six legally required data: type of service, person served, worker, service date, start/end times, service location. GPS capture only with explicit device permission; \`location denied\` must initiate regulated alternate verification or human exception workflow, never silently assert GPS verified. Maintain immutable corrections and jurisdiction/payer-specific provider integrations. EVV not equivalent to payroll unless payroll integration exists. Reference federal 21st Century Cures Act/CMS.
- Offline: local encrypted device-bound draft store with explicit retention and key-protection plan, visit/clinical note save into durable queue, visible \`Pending sync\`, reconnect synchronization, server timestamp, idempotency key, conflict resolution and 403 fail-closed on lost assignment. Never state \`Synced\` until backend ack. Existing status indicator is NOT offline queue.
- Care plan mandatory tasks must be task-specific and linked to patient+visit+actor; medication reminders are not authorization to prescribe/administer. Photograph medication only if validated source and permission; never infer doses from images.
- Incident report: high-priority single-page form with severity, time, patient, optional permitted photo, no exposure to personal SMS/camera sync; critical incident creates Director alert. Messaging within audited PHI-safe Haneen threads.
- \`AI Policy Assistant\` optional, retrieval-augmented over versioned organization policies ONLY; patient-specific advice/clinical diagnosis/medication recommendations disabled without validated safety protocol and human review.
- First increment on this branch adds six direct actions to existing production-verified nav (schedule, visits, tasks, patients, incidents, communication). The current dashboard already has five clickable KPIs; preserve them.
