## Evidence interpretation

The hosted SQL negative tests deliberately seed synthetic billing state inside a transaction only to prove that activation is refused. The marker `SYNTHETIC-NOT-A-STRIPE-SUBSCRIPTION` is explicitly not a Stripe reference. These tests do not establish payment, agreement execution, credential verification, production readiness, or successful provisioning. Each script ends in ROLLBACK. No clinical data or existing user state was changed by these tests.

The first two negative-test attempts failed on fixture constraints (`director_requires_proposed_name`, then `professional_applications_draft_allows_null_identity`). Fixtures were corrected; both failed transactions were aborted. The final 24-case run passed. This was test-fixture correction, not relaxation of application constraints.

## Exact access/configuration blockers

1. **Agreement boundary:** identify the already approved signing provider/process and provide the approved SaaS license and BAA template versions, authoritative document content/references, authorized signatory/countersignature requirements, and sandbox signing access. The repository contains a contract evidence registry, not an operational self-service signature integration. Do not infer approval for a new provider.
2. **Payment boundary:** staging function inventory contains only `provision-caregiver-patient`, `delete-pending-registration`, `regenerate-activation-link`, and `download-message-attachment`. Repository functions `create-enterprise-checkout-session`, `create-enterprise-monthly-subscription`, `create-enterprise-billing-portal-session`, and `stripe-webhook` are absent. Supabase Stripe secret values/test-mode status and webhook registration cannot be verified with available access. No local Stripe/Supabase management credentials were found. Configure approved Stripe **test-mode** credentials, webhook endpoint/signing secret, and correct return URL before executing provider tests. Do not paste secrets into a report or commit them.
3. **Browser boundary:** opening `https://mymemoria-professional.vercel.app/` redirects to Vercel login. Vercel project reports SSO protection on all deployments. Authenticated plugin HTTP fetch of `/Professional/Register` returns 200 and Haneen HTML, but that does not authenticate this browser or prove React interaction. Browser authentication is needed; do not disable protection to obtain a pass.
4. **Disposable-runtime boundary:** no Docker executable; integration helpers intentionally reject unspecified targets. Chromium download via Playwright failed with `End of central directory record signature not found`. Keep that failure separate from application defects.

## Deployment safety

No production deployment was attempted. The externally named production website is currently configured with Vercel environment comments identifying the Supabase connection as **staging only** and the production database connection as intentionally withheld. Therefore even an accessible website on the production hostname would not prove production backend readiness. No protected environment values were exposed or changed.

Do not promote until all eight rows have functional evidence tied to the same release SHA and the intended production backend. Stop on missing legal execution, unverified payment, unexpected tenant access, duplicate organization/license/Director creation, or unauthorized dashboard access. After eventual promotion, smoke-test all three tiers against the deployed SHA and roll back traffic on a critical failure.
